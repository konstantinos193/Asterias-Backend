# Edge proxy: Traefik + CrowdSec

Replaces the host nginx on 194.99.21.157. One box, one `:80`/`:443` pair, five
vhosts across four unrelated projects — so this is a whole-box conversion, not
an asterias-only one.

```
internet
   │
   ▼
Traefik v3.6  (host network, :80 → :443)
   │   entrypoint middleware chain, in order:
   │     1. crowdsec          IP reputation + WAF        → 403
   │     2. security-headers  HSTS, nosniff, CSP, frame-deny
   │     3. rate-limit        50/s per IP, burst 100     → 429
   │     4. inflight          40 concurrent per IP       → 429
   ▼
127.0.0.1:<port>  →  asterias 5010/5011 · kyklos 8081 · adinfinity 3011
                     mail 8080 (stalwart, on the host) · melissourgoi 8082
```

CrowdSec runs beside it: it parses Traefik's JSON access log, decides who to
ban, and serves those decisions to the Traefik plugin. The plugin keeps them in
a local cache refreshed every 60s, so a banned IP costs a map lookup.

## Files

| File | What it is |
|---|---|
| `traefik.yml` | Static config. Entrypoints, providers, plugin pin. Restart to apply. |
| `dynamic/middlewares.yml.template` | The protection chain. **Edit this one.** |
| `dynamic/middlewares.yml` | Generated by `install.sh` with the bouncer key substituted. Gitignored. |
| `dynamic/routers.yml` | The five vhosts, 1:1 with the old nginx sites-enabled. |
| `dynamic/services-asterias.yml` | Blue/green target. Rewritten by `scripts/deploy.sh`. |
| `dynamic/tls.yml` | Certificates (certbot's) + TLS 1.2 floor and cipher policy. |
| `crowdsec/acquis.yaml` | Log source + the AppSec listener on :7422. |
| `crowdsec/appsec-configs/appsec-api.yaml` | Which WAF rules load, and why. |
| `crowdsec/profiles.yaml` | Ban durations, with escalation for repeat offenders. |

Anything under `dynamic/` is hot-reloaded on write. `traefik.yml` is not.

## Running it

```bash
bash install.sh       # stage on :8070/:8453, alongside the live nginx
bash validate.sh      # 16 checks; must be 0 FAIL
bash cutover.sh       # take :80/:443 (the only step with an outage window)
bash enable-acme.sh   # hand certificates to Traefik; run AFTER cutover
bash cutover.sh rollback
```

`cutover.sh` re-checks every vhost after the flip and rolls itself back to nginx
if any of them is down, so a bad cutover self-heals rather than sitting broken.

## Things that will bite you

**A probe from the server itself proves nothing.** `127.0.0.1` is in
`clientTrustedIPs`, so requests from the box bypass the bouncer and the WAF
entirely. Local curl returns 200 and looks like the WAF is broken. Test from a
workstation — `validate.sh` prints the exact commands.

**Testing the WAF bans you for 12h.** Clear it with
`docker exec crowdsec cscli decisions delete --all`, then wait ~60s for the
stream cache.

**`inFlightReq` defaults to `requestHost`, not the client IP.** Left at the
default it is one shared pool of 40 for everybody on a host, which a single
slow client can starve. The explicit `ipStrategy` in the template is what makes
it per-IP. Don't remove it.

**Don't set `ipStrategy.depth: 1`.** Traefik appends the previous hop to
`X-Forwarded-For` *after* middlewares run, so at middleware time that header
holds only what the client sent — attacker-controlled. `depth: 0` (the TCP
remote address) is correct while Traefik is the first hop. If Cloudflare ever
goes in front, that changes, and `forwardedHeadersTrustedIPs` must be filled in
at the same time.

**The entrypoint needs `tls: {}` even with no cert resolver.** A router is
either TLS or plain-HTTP. Remove that block and every router silently becomes
plain-HTTP, HTTPS matches nothing, and the entrypoint answers its own 404 while
still serving a valid certificate. It looks exactly like a routing bug.

**Traefik ignores `--entryPoints.*` CLI flags when a static file is mounted.**
The sources are mutually exclusive, not merged. That is why staging mounts a
generated `traefik.staging.yml` instead of passing ports on the command line.

**CORS is not set here on purpose.** Nest already emits it. Two sets of
`Access-Control-Allow-Origin` is an immediate browser CORS failure.

## The limit most likely to break the site

The frontend is on Vercel and renders server-side, so **every SSR request to
this API arrives from a handful of Vercel egress IPs**, not from visitors'
addresses. A per-IP limit therefore applies to the whole site's server-side
traffic at once. Current headroom per IP is 50 req/s (burst 100) and 40
concurrent, which is generous for this traffic level — but if the site starts
showing intermittent failures under load, check for 429s before anything else:

```bash
docker exec traefik sh -c \
  'grep -c "\"DownstreamStatus\":429" /var/log/traefik/access.log'
```

Raise `rate-limit` / `inflight` in the template, re-run `install.sh`. Vercel
does not publish stable egress IPs without Secure Compute, so allowlisting them
is not an option.

## Certificates

Traefik currently *reads* certbot's certs; it does not manage them. They are
valid to 2026-12-23.

certbot was installed with the nginx plugin, which cannot renew once nginx is
stopped. The decision has been made to hand issuance to Traefik — run
`enable-acme.sh` after the cutover. It edits `traefik.yml` (keeping a `.bak`),
recreates Traefik, then checks each domain's served certificate serial against
the one on disk to tell a Traefik-issued cert from certbot's leftover.

It refuses to run unless Traefik is already listening on :443, because TLS-ALPN
validates on that port. It is safe to run with no window: the certbot certs keep
being served until ACME has a replacement, so a failed issuance means "still on
the old cert", not a TLS outage.

`api.melissourgoi.dev` has no DNS record at all, so it has no certificate and
cannot get one. Its router is kept but it serves no real traffic; it is left out
of the cutover health gate deliberately.

## What this does and does not stop

Stops: known-bad IPs (CrowdSec community blocklist), CVE and path probes,
generic SQLi / XSS / traversal / command injection (OWASP CRS, inband),
credential stuffing (10 per 10s on `/api/auth`), Puppeteer PDF abuse (2
concurrent, 5/min), slow-loris, request floods, oversized bodies.

Does not stop: a distributed flood large enough to saturate a 1-vCPU 2GB VPS's
uplink. Nothing running *on* the box can, because the traffic arrives either
way. The only real answer is a network in front — Cloudflare's free tier on
these DNS records would absorb it and is the single biggest remaining win.

**No JS/captcha bot challenge is enabled, on purpose.** CrowdSec 1.8 ships one
(`appsec-bot-challenge-*`), but every vhost here is a JSON API. Stripe and
Booking.com webhooks, iCal consumers and Vercel's server-side fetches cannot
solve a browser challenge, so enabling it would break paying integrations to
deter bots that the IP blocklist and CRS already handle. It belongs on an HTML
frontend, not here.

## Day-to-day

```bash
docker exec crowdsec cscli alerts list              # what fired
docker exec crowdsec cscli alerts list --kind waf   # WAF hits (false positives live here)
docker exec crowdsec cscli decisions list           # who is banned
docker exec crowdsec cscli metrics show appsec      # per-rule trigger counts
docker exec crowdsec cscli decisions delete --ip X.X.X.X

ssh -L 8099:127.0.0.1:8099 asterias   # then http://127.0.0.1:8099/dashboard/
                                      # credentials are in traefik/.env
```

Memory, measured with everything running: Traefik ~40MB, CrowdSec ~85MB, ~1.0GB
still available. Both have hard `mem_limit`s so that if the WAF misbehaves it is
killed alone. The middleware is configured to **fail open** — a dead CrowdSec
degrades protection rather than taking four clients' APIs down. That also means
a broken bouncer looks fine from outside, which is why `validate.sh` checks it
from the inside.
